# Спецификация требований

## 1. Первичный список требований

Каждое из требований, предъявляемых к проектируемой системе, имеет один из следующих приоритетов:
* **H** — высокий
* **M** — средний
* **L** — низкий

Категория определяет приоритет выполнения требований на последующих стадиях. Первыми реализуются требования с высоким приоритетом, вторыми — со средним, третьими — с низким. Предполагается, что требования с высоким приоритетом будут выполнены даже в худших условиях.

### 1. Управление учетной записью и личным кабинетом
* **1.1** Пользователь имеет возможность зарегистрировать учетную запись. **(H)**
* **1.2** Пользователь имеет возможность авторизоваться в системе. **(H)**
* **1.3** Обучающийся имеет возможность просматривать основные результаты обучения в личном кабинете. **(M)**

### 2. Изучение математических тем
* **2.1** Система предоставляет обучающемуся возможность просматривать список математических тем. **(H)**
* **2.2** Обучающийся имеет возможность выбирать математическую тему для изучения. **(H)**
* **2.3** Обучающийся имеет возможность просматривать теоретические материалы по выбранной теме. **(H)**
* **2.4** Обучающийся имеет возможность повторно проходить задания по выбранной теме для закрепления материала. **(L)**

### 3. Выполнение и проверка математических заданий
* **3.1** Обучающийся имеет возможность выбирать математические задания различных типов. **(H)**
* **3.2** Система отображает условие выбранного задания. **(H)**
* **3.3** Система принимает решение (ответ) обучающегося на задание. **(H)**
* **3.4** Система автоматически выполняет проверку решения. **(H)**
* **3.5** Система отображает результат проверки решения. **(H)**
* **3.6** Система предоставляет обучающемуся объяснение правильного решения или информацию о допущенной ошибке. **(H)**
* **3.7** При недоступности ИИ-модуля система предоставляет обучающемуся заранее подготовленные задания из базы данных. **(H)**

### 4. Учет результатов и анализ успеваемости
* **4.1** Система сохраняет историю решений в учетной записи обучающегося. **(H)**
* **4.2** Система автоматически формирует показатели успеваемости по результатам выполнения заданий. **(H)**
* **4.3** Система отображает обучающемуся его успеваемость и образовательный прогресс по математическим темам. **(H)**
* **4.4** Обучающийся имеет возможность просматривать образовательный прогресс по отдельным математическим темам. **(H)**
* **4.5** Система определяет темы, в которых обучающийся чаще всего допускает ошибки. **(M)**
* **4.6** Система, на основе допущенных ошибок, выделяет слабые места. **(M)**

### 5. Адаптивное и интеллектуальное обучение
* **5.1** Система адаптирует сложность предлагаемых заданий на основе результатов предыдущих попыток обучающегося. **(M)**
* **5.2** Система автоматически генерирует новые математические задания с использованием ИИ-модуля GigaChat. **(M)**

### 6. Игровая система и достижения
* **6.1** Обучающийся имеет возможность запускать игровой режим «Испытание». **(M)**
* **6.2** Система начисляет обучающемуся очки опыта за правильное выполнение заданий и прохождение игрового режима. **(M)**
* **6.3** Система автоматически изменяет магический ранг пользователя в зависимости от количества накопленного опыта. **(M)**
* **6.4** Система предоставляет обучающемуся возможность просматривать полученные достижения и текущий магический ранг в профиле. **(M)**

## 1.1. Ограничения

* **Язык интерфейса:** Интерфейс веб-приложения реализован полностью на русском языке.
* **Доступность:** Приложение доступно через браузер на компьютере, планшете или смартфоне; отдельное мобильное или десктопное приложение не разрабатывается.
* **Учетные записи:** Доступ к тренажеру, статистике и достижениям предоставляется только авторизованным пользователям. Весь прогресс и ранги сохраняются в привязке к аккаунту. *(ФТ: 1.1–1.3, 4.1, 6.4)*
* **Содержание обучения:** Содержание тренажера и теоретических материалов ограничено школьной программой по математике для 5 класса. *(ФТ: 2.1–2.3)*
* **Игровые механики:** В качестве интерактивного соревновательного элемента в приложении реализован один игровой режим ("Испытание"). *(ФТ: 6.1–6.4)*
* **Интеграция ИИ:** Для динамической генерации математических заданий и адаптации их сложности используется внешний ИИ-модуль GigaChat от Сбера. Работоспособность тренажера не должна полностью зависеть от доступности API ИИ-модуля. *(ФТ: 3.7, 5.1–5.2)*
* **Форматы заданий:** Поддерживаются только предусмотренные форматы: выбор ответа, ввод значения, сопоставление пар, правда/ложь, расстановка действий. Задания с геометрическими построениями или загрузкой изображений решения не поддерживаются. *(ФТ: 3.1–3.3)*
* **Проверка ответов:** Система проверяет только заданный ответ/набор пар, развернутые решения и промежуточные шаги не анализируются. *(ФТ: 3.3–3.6)*
* **Офлайн-режим:** Работа приложения требует постоянного подключения к серверу, офлайн-доступ к заданиям и статистике не предусмотрен.

## 2. Модели требований

### 2.1. Модель предметной области

**Объекты:**
* **Обучающийся (Ученик)** — лицо, осваивающее школьный курс математики за 5 класс.
* **Математическая тема** — раздел школьной программы за 5 класс (например, натуральные числа, обыкновенные дроби, проценты, текстовые задачи), объединяющий теорию и практику.
* **Теоретический материал** — свод правил, определений, формул и примеров, объясняющих математическую тему.
* **Задание** — математический пример, упражнение, требующее решения.
* **Решение** — результат выполнения обучающимся предложенного задания.
* **Проверка решения** — сопоставление полученного ответа с правильным решением с целью определения его верности.
* **Успеваемость** — показатели освоения математических тем, фиксирующие количество правильно и ошибочно решенных заданий.
* **Образовательный прогресс** — накопленный опыт, уровень знаний обучающегося в процессе изучения математики.

**Связи:**
* **Изучение темы** — обучающийся выбирает математическую тему для ознакомления с теоретическим материалом.
* **Выполнение задания** — обучающийся выбирает задание из темы и формирует на него ответ (решение).
* **Оценка результата** — решение задания проходит проверку на правильность.
* **Накопление оценок** — результаты проверки решений обновляют общую статистику успеваемости обучающегося.
* **Фиксация прогресса** — успешное освоение тем и решение задач увеличивают опыт обучающегося.

### 2.1.1. Модель пользователей системы

Права пользователей наследуются по иерархии. Каждый вышестоящий тип пользователя обладает правами подчиненных ему типов, а также дополнительными, уникальными правами.

#### Роль 1: Неавторизованный пользователь (гость)
* **Навыки:** Базовые навыки работы с веб-браузером.
* **В распоряжении:** Устройство с доступом в интернет и браузер.
* **Доступный интерфейс:** Главная страница приложения, страница авторизации и регистрации.
* **Функциональные права и возможности:**
  * Регистрация учетной записи (ФТ 1.1)
  * Авторизация в системе (ФТ 1.2)

#### Роль 2: Авторизованный пользователь (обучающийся)
* **Навыки:** Базовые навыки работы в интернете, ввод текста и чисел, начальные знания математики за 5 класс.
* **В распоряжении:** Личный аккаунт, устройство с браузером и интернетом.
* **Доступный интерфейс:** Дашборд с выбором тем, страница теории, интерфейс тренажера для решения задач, игровой режим ("Испытание"), личный кабинет со статистикой, рангом и достижениями.
* **Функциональные права и возможности:**
  * Управление личным кабинетом: просмотр основных результатов обучения (ФТ 1.3)
  * Изучение тем: просмотр списка тем, выбор темы, просмотр теории и повторное прохождение заданий (ФТ 2.1, 2.2, 2.3, 2.4)
  * Выполнение и проверка заданий: выбор заданий, просмотр условий, отправка и проверка ответов, получение обратной связи, а также получение заранее подготовленных заданий при недоступности ИИ-модуля (ФТ 3.1, 3.2, 3.3, 3.4, 3.5, 3.6, 3.7)
  * Учет результатов и анализ: сохранение истории, формирование и просмотр статистики и успеваемости по темам, выявление слабых мест (ФТ 4.1, 4.2, 4.3, 4.4, 4.5, 4.6)
  * Адаптивное обучение и ИИ: адаптация сложности заданий и генерация через GigaChat (ФТ 5.1, 5.2)
  * Игровая система: запуск режима «Испытание», начисление опыта, изменение рангов и просмотр достижений (ФТ 6.1, 6.2, 6.3, 6.4)

#### Роль 3: Администратор
* **Навыки:** Навыки управления веб-приложениями и базами данных.
* **В распоряжении:** Учетная запись администратора с доступом к панели управления администратора (Django Admin).
* **Доступный интерфейс:** Интерфейс админ-панели для управления базой данных тем, задач, пользователей и мониторинга работы ИИ-модуля GigaChat.
* **Функциональные права и возможности (включая все права пользователя):**
  * Управление контентом обучения: добавление, редактирование и удаление математических тем, теоретических материалов и задач (ФТ 2.1, 3.1)
  * Управление пользователями: просмотр списка учетных записей, блокировка или разблокировка пользователей при нарушении правил, сброс учетных данных.
  * Мониторинг интеграции: отслеживание статуса соединения с внешним API GigaChat, проверка срабатывания резервного источника базы данных (ФТ 3.7, 5.2)
  * Анализ системных логов: просмотр истории попыток и системных ошибок для обеспечения стабильности веб-приложения.

**Создание учетной записи администратора:**
* Учетная запись первого администратора создается разработчиком с помощью штатной команды Django `python manage.py createsuperuser`.
* Самостоятельная регистрация пользователей с правами администратора не предусмотрена.
* Администратор проходит авторизацию с использованием своей учетной записи и получает доступ к панели Django Admin.
* Права доступа администратора определяются встроенной системой разрешений Django.

### 2.2. Функциональная модель

Функциональная модель описывает основные сценарии взаимодействия пользователя с системой «МатеМагия» в соответствии с функциональными требованиями.

* **Сценарий 1 (к ФТ 1.1): Регистрация учетной записи**
  * *Предварительные условия:* Пользователь не авторизован в системе, открыта страница регистрации.
  * Пользователь вводит данные новой учетной записи и отправляет форму регистрации.
  * Система проверяет введенные данные и создает новую учетную запись.

* **Сценарий 2 (к ФТ 1.2): Авторизация в системе**
  * *Предварительные условия:* Пользователь имеет зарегистрированную учетную запись, открыта страница авторизации.
  * Пользователь вводит данные учетной записи и подтверждает вход.
  * Система проверяет введенные данные и предоставляет пользователю доступ к системе.

* **Сценарий 3 (к ФТ 2.1): Просмотр списка математических тем**
  * *Предварительные условия:* Обучающийся авторизован в системе и имеет доступ к разделу обучения.
  * Обучающийся переходит в раздел выбора математических тем.
  * Система отображает список доступных математических тем за 5 класс.

* **Сценарий 4 (к ФТ 2.2): Выбор математической темы**
  * *Предварительные условия:* Обучающийся авторизован в системе, отображен список доступных математических тем.
  * Обучающийся выбирает математическую тему для изучения.
  * Система открывает выбранную тему и отображает доступные материалы.

* **Сценарий 5 (к ФТ 2.3): Просмотр теоретических материалов**
  * *Предварительные условия:* Обучающийся авторизован в системе и выбрал математическую тему, для которой доступны теоретические материалы.
  * Обучающийся выбирает просмотр теоретических материалов по выбранной теме.
  * Система отображает теоретические материалы по данной теме.

* **Сценарий 6 (к ФТ 3.1): Выбор математического задания**
  * *Предварительные условия:* Обучающийся авторизован в системе, выбрана математическая тему с доступными заданиями.
  * Обучающийся выбирает тип математического задания.
  * Система предоставляет обучающемуся задание выбранного типа.

* **Сценарий 7 (к ФТ 3.2): Отображение условия задания**
  * *Предварительные условия:* Обучающийся авторизован в системе, выбранное задание доступно для выполнения.
  * Обучающийся открывает выбранное математическое задание.
  * Система отображает условие выбранного задания.

* **Сценарий 8 (к ФТ 3.3): Отправка решения**
  * *Предварительные условия:* Обучающийся авторизован в системе, открыто математическое задание с возможностью ввода ответа.
  * Обучающийся вводит решение (ответ) на математическое задание и отправляет его.
  * Система принимает введенный обучающимся ответ.

* **Сценарий 9 (к ФТ 3.4): Проверка решения**
  * *Предварительные условия:* Обучающийся авторизован в системе, задание имеет эталонный ответ для проверки.
  * Обучающийся отправляет решение математического задания на проверку.
  * Система автоматически проверяет правильность введенного ответа.

* **Сценарий 10 (к ФТ 3.5): Отображение результата проверки**
  * *Предварительные условия:* Обучающийся отправил решение задания, система выполнила его проверку.
  * Обучающийся завершает отправку решения на проверку.
  * Система отображает результат проверки решения (верно или неверно).

* **Сценарий 11 (к ФТ 3.6): Получение объяснения решения**
  * *Предварительные условия:* Обучающийся авторизован в системе, решение задания проверено и получен результат проверки.
  * Обучающийся завершает попытку решения задания.
  * Система предоставляет объяснение правильного решения или информацию о допущенной ошибке.

* **Сценарий 12 (к ФТ 4.1): Сохранение истории решений**
  * *Предварительные условия:* Обучающийся авторизован в системе и выполняет математическое задание.
  * Обучающийся завершает решение математического задания.
  * Система сохраняет результат решения в истории учетной записи обучающегося.

* **Сценарий 13 (к ФТ 4.2): Формирование показателей успеваемости**
  * *Предварительные условия:* Обучающийся авторизован в системе, доступна история выполненных заданий.
  * Обучающийся выполняет математическое задание.
  * Система на основе результата выполнения автоматически обновляет показатели успеваемости обучающегося.

* **Сценарий 14 (к ФТ 4.3): Просмотр общей успеваемости**
  * *Предварительные условия:* Обучающийся авторизован в системе, данные об успеваемости доступны в его учетной записи.
  * Обучающийся открывает раздел статистики.
  * Система отображает успеваемость обучающегося и общий образовательный прогресс по математическим темам.

* **Сценарий 15 (к ФТ 4.4): Просмотр прогресса по отдельной теме**
  * *Предварительные условия:* Обучающийся авторизован в системе, открыта страница статистики с доступными математическими темами.
  * Обучающийся выбирает математическую тему в разделе статистики.
  * Система отображает образовательный прогресс обучающегося по выбранной теме.

* **Сценарий 16 (к ФТ 4.5): Определение проблемных тем**
  * *Предварительные условия:* Обучающийся авторизован в системе, сохранена история решений по математическим темам.
  * Обучающийся выполняет задания по математическим темам.
  * Система анализирует допущенные ошибки и определяет темы, в которых обучающийся ошибается чаще всего.

* **Сценарий 17 (к ФТ 4.6): Выделение слабых мест**
  * *Предварительные условия:* Обучающийся авторизован в системе, имеются результаты проверки решений и данные о допущенных ошибках.
  * Обучающийся открывает раздел статистики после выполнения заданий.
  * Система анализирует результаты обучающегося и выделяет выявленные слабые места.

* **Сценарий 18 (к ФТ 6.1): Запуск игрового режима «Испытание»**
  * *Предварительные условия:* Обучающийся авторизован в системе, игровой режим «Испытание» доступен для запуска.
  * Обучающийся выбирает игровой режим «Испытание».
  * Система запускает игровой режим и предоставляет обучающемуся первое задание.

* **Сценарий 19 (к ФТ 6.2): Начисление очков опыта**
  * *Предварительные условия:* Обучающийся авторизован в системе, выполняет математическое задание или проходит игровой режим.

## 3. Высокоуровневая архитектура системы

Архитектура веб-приложения «МатеМагия» построена по клиент-серверной модели с использованием паттерна MVC (Model-View-Controller), реализованного средствами фреймворка Django. Система разделена на компоненты, что обеспечивает модульность, масштабируемость и простоту поддержки.

### 3.1. Модель архитектуры

#### 3.1.1. Компоненты системы

1. **Клиентский уровень**
   * Представлен веб-браузером, через который обучающийся взаимодействует с приложением.
   * Обеспечивает отображение интерфейсов регистрации и авторизации, выбора математических тем, теоретических материалов, тренажёра заданий, личного кабинета и игрового режима «Испытание».
   * Отправляет HTTP-запросы на сервер Django и отображает полученные ответы.

2. **Серверный уровень – Django**
   * Обеспечивает обработку входящих HTTP-запросов и управление взаимодействием между различными компонентами системы.
   * **Django URL** — выполняет маршрутизацию запросов к соответствующим обработчикам.
   * **Django Views** — обрабатывает запросы пользователей, вызывает необходимые функциональные модули и формирует ответы.
   * **Django-приложения** — разделяют функциональность системы на пять модулей:
     * *Приложение пользователей* — регистрация, авторизация и управление учётными записями.
     * *Приложение обучения* — просмотр и выбор математических тем, отображение теоретических материалов.
     * *Приложение заданий и тестов* — предоставление заданий, приём и проверка ответов, отображение результатов и объяснений.
     * *Приложение прогресса* — сохранение результатов, формирование статистики, анализ ошибок и отображение прогресса.
     * *Приложение игрового режима* — реализация режима «Испытание», начисление опыта, изменение магического ранга и учёт достижений.
   * **Бизнес-логика** — реализует алгоритмы проверки ответов, расчёта успеваемости, выявления слабых мест, адаптации сложности заданий и начисления игрового опыта.
   * **Django ORM** — обеспечивает взаимодействие серверной части с базой данных посредством моделей Python.

3. **Уровень данных**
   * Представлен базой данных SQLite.
   * Управляется с помощью встроенного фреймворка Django.
   * Хранит информацию об учётных записях пользователей, математических темах, теоретических материалах, заданиях, истории попыток решений, статистике, образовательном прогрессе, опыте, рангах и достижениях.

4. **Внешний уровень**
   * **API GigaChat** — внешний сервис искусственного интеллекта, используемый для динамической генерации математических заданий и поддержки адаптивного обучения.
   * Серверная часть формирует запрос к API GigaChat и обрабатывает полученный ответ.
   * При недоступности внешнего API система предоставляет заранее подготовленные задания из базы данных.

## 4. Детальные требования к компонентам системы

Детальные требования определяют обязанности компонентов веб-приложения «МатеМагия» в соответствии с высокоуровневой архитектурой системы. Требования сгруппированы по архитектурным компонентам, а не по группам функциональных требований. После каждого требования указаны связанные функциональные требования (ФТ).

Django-приложения являются функциональными частями серверной системы, а Django URL, Django Views, бизнес-логика и Django ORM — механизмами, используемыми внутри этих приложений. Их выделение в отдельные разделы позволяет уточнить обязанности компонентов без предположения, что они обязательно реализуются как независимые программы.

### 4.1. Клиентский уровень (Frontend)
Клиентский уровень отвечает за отображение интерфейса и передачу действий пользователя серверу.
* Клиентский интерфейс должен предоставлять формы регистрации и авторизации. *(ФТ 1.1, 1.2)*
* Клиентский интерфейс должен отображать список математических тем и материалы выбранной темы. *(ФТ 2.1, 2.2, 2.3)*
* Клиентский интерфейс должен предоставлять элементы выбора типа математического задания и ввода ответа, соответствующие формату задания. *(ФТ 3.1, 3.3)*
* Клиентский интерфейс должен отображать условие текущего математического задания. *(ФТ 3.2)*
* Клиентский интерфейс должен отображать результат проверки ответа и объяснение решения либо информацию об ошибке. *(ФТ 3.5, 3.6)*
* Клиентский интерфейс должен отображать в личном кабинете основные показатели успеваемости и прогресс по отдельным темам. *(ФТ 1.3, 4.3, 4.4)*
* Клиентский интерфейс должен предоставлять доступ к игровому режиму «Испытание» и отображать ранг и достижения обучающегося. *(ФТ 6.1, 6.4)*
* Клиентский интерфейс должен обеспечивать использование предусмотренных функций в браузере компьютера, планшета или смартфона. *(Ограничение «Доступность»)*

### 4.2. Маршрутизация запросов (Django URL)
Компонент Django URL определяет соответствие адресов приложения обработчикам пользовательских запросов.
* Компонент должен направлять запросы регистрации и авторизации соответствующим обработчикам приложения пользователей. *(ФТ 1.1, 1.2)*
* Компонент должен направлять запросы просмотра списка тем и теоретических материалов обработчикам приложения обучения. *(ФТ 2.1, 2.2, 2.3)*
* Компонент должен направлять запросы получения заданий и отправки ответов обработчикам приложения заданий и тестов. *(ФТ 3.1, 3.2, 3.3)*
* Компонент должен направлять запросы личного кабинета и статистики обработчикам приложения пользователей или прогресса. *(ФТ 1.3, 4.3, 4.4)*
* Компонент должен направлять запросы запуска игрового режима и просмотра достижений обработчикам игрового приложения. *(ФТ 6.1, 6.4)*

### 4.3. Обработка запросов (Django Views)
Компонент Django Views принимает HTTP-запросы, вызывает необходимую логику приложений и формирует ответы для браузера.
* Обработчики должны принимать данные форм регистрации и передавать их на проверку и создание учетной записи. *(ФТ 1.1)*
* Обработчики должны принимать данные авторизации и инициировать проверку учетных данных. *(ФТ 1.2)*
* Обработчики должны запрашивать список тем и материалы выбранной темы для формирования ответа клиенту. *(ФТ 2.1, 2.2, 2.3)*
* Обработчики должны получать задание по выбранным параметрам и передавать клиенту его условие. *(ФТ 3.1, 3.2)*
* Обработчики должны принимать отправленный ответ и передавать его соответствующей бизнес-логике проверки. *(ФТ 3.3, 3.4)*
* Обработчики должны включать результат проверки и обратную связь в ответ, возвращаемый клиенту. *(ФТ 3.5, 3.6)*
* Обработчики должны запрашивать данные об успеваемости для отображения личного кабинета и статистики по темам. *(ФТ 1.3, 4.3, 4.4)*

### 4.4. Приложение пользователей
Приложение пользователей отвечает за учетные записи, авторизацию и доступ к личному кабинету.
* Приложение должно получать и проверять данные, введенные при регистрации. *(ФТ 1.1)*
* Приложение должно создавать учетную запись при успешной проверке регистрационных данных. *(ФТ 1.1)*
* Приложение должно сообщать о некорректных данных или невозможности регистрации. *(ФТ 1.1)*
* Приложение должно проверять учетные данные пользователя при авторизации. *(ФТ 1.2)*
* Приложение должно создавать пользовательскую сессию при успешной авторизации. *(ФТ 1.2)*
* Приложение должно ограничивать доступ неавторизованных пользователей к тренажеру, статистике и личному кабинету. *(ФТ 1.2, 1.3)*
* Приложение должно предоставлять для личного кабинета основные результаты обучения, связанные с учетной записью пользователя. *(ФТ 1.3)*

### 4.5. Приложение обучения
Приложение обучения управляет математическими темами и теоретическими материалами.
* Приложение должно получать список доступных математических тем. *(ФТ 2.1)*
* Приложение должно предоставлять для изучения темы, относящиеся к программе математики за 5 класс. *(ФТ 2.1)*
* Приложение должно обрабатывать выбор математической темы обучающимся. *(ФТ 2.2)*
* Приложение должно определять теоретические материалы, связанные с выбранной темой. *(ФТ 2.3)*
* Приложение должно предоставлять правила, определения, формулы и примеры по выбранной теме. *(ФТ 2.3)*
* Приложение должно передавать выбранную математическую тему в приложение заданий и тестов при переходе к практике. *(ФТ 2.2, 3.1)*
* Приложение должно предоставлять возможность повторного прохождения заданий по ранее выбранной теме. *(ФТ 2.4)*

### 4.6. Приложение заданий и тестов
Приложение заданий и тестов организует получение заданий, прием ответов и передачу результатов проверки клиенту.
* Приложение должно предоставлять обучающемуся выбор формата математического задания. *(ФТ 3.1)*
* Приложение должно поддерживать задания с выбором ответа и вводом числового значения. *(ФТ 3.1)*
* Приложение должно поддерживать задания на сопоставление пар, «Правда/ложь» и расстановку действий. *(ФТ 3.1)*
* Приложение должно подбирать задание в соответствии с выбранной математической темой и форматом. *(ФТ 3.1)*
* Приложение должно предоставлять условие выбранного математического задания. *(ФТ 3.2)*
* Приложение должно принимать ответ обучающегося на текущее задание. *(ФТ 3.3)*
* Приложение должно проверять соответствие структуры полученного ответа формату задания и передавать ответ на автоматическую проверку. *(ФТ 3.3, 3.4)*
* Приложение должно предоставлять клиенту статус проверки и объяснение правильного решения либо сведения об ошибке. *(ФТ 3.5, 3.6)*
* Приложение должно выдавать заранее подготовленное задание из базы данных при недоступности сервиса GigaChat. *(ФТ 3.7)*

### 4.7. Приложение прогресса и статистики
Приложение прогресса отвечает за историю попыток и представление результатов обучения.
* Приложение должно фиксировать каждую завершенную попытку решения математического задания. *(ФТ 4.1)*
* Приложение должно связывать результат попытки с обучающимся, математической темой и заданием. *(ФТ 4.1)*
* Приложение должно учитывать повторные попытки выполнения задания. *(ФТ 4.1)*
* Приложение должно передавать сведения об истории попыток для расчета показателей успеваемости. *(ФТ 4.2)*
* Приложение должно предоставлять общее количество решенных заданий, количество верных и неверных ответов и процент успешных решений. *(ФТ 4.2)*
* Приложение должно предоставлять сводные сведения об образовательном прогрессе обучающегося. *(ФТ 4.3)*
* Приложение должно предоставлять показатели прогресса отдельно по выбранной математической теме. *(ФТ 4.4)*
* Приложение должно предоставлять результаты анализа ошибок, включая проблемные темы и выявленные слабые места. *(ФТ 4.5, 4.6)*

### 4.8. Приложение игрового режима
Приложение игрового режима отвечает за проведение «Испытания» и учет игровых результатов.
* Приложение должно предоставлять авторизованному обучающемуся возможность запустить режим «Испытание». *(ФТ 6.1)*
* Приложение должно создавать игровую сессию при запуске режима. *(ФТ 6.1)*
* Приложение должно запрашивать математические задания для прохождения игровой сессии. *(ФТ 6.1)*
* Приложение должно фиксировать результат завершенного испытания. *(ФТ 6.1)*
* Приложение должно инициировать начисление очков опыта за правильное выполнение заданий и успешное прохождение режима. *(ФТ 6.2)*
* Приложение должно применять результат расчета магического ранга после изменения накопленного опыта. *(ФТ 6.3)*
* Приложение должно предоставлять сведения о текущем магическом ранге и полученных достижениях для отображения в профиле. *(ФТ 6.4)*

### 4.9. Бизнес-логика
Компонент бизнес-логики выполняет правила обработки ответов, расчета успеваемости, адаптации заданий и игровой прогрессии.
* Компонент должен обрабатывать полученный ответ с учетом формата математического задания. *(ФТ 3.3, 3.4)*
* Компонент должен сравнивать ответы в заданиях с выбором варианта или вводом значения с эталонными ответами. *(ФТ 3.4)*
* Компонент должен проверять ответы на сопоставление пар, «Правда/ложь» и расстановку действий по правилам соответствующего формата. *(ФТ 3.4)*
* Компонент должен определять результат проверки ответа: правильный или неправильный. *(ФТ 3.5)*
* Компонент должен формировать объяснение правильного решения или информацию о допущенной ошибке. *(ФТ 3.6)*
* Компонент должен рассчитывать показатели успеваемости на основе сохраненных результатов выполнения заданий. *(ФТ 4.2)*
* Компонент должен анализировать ошибки и определять проблемные математические темы и слабые места обучающегося. *(ФТ 4.5, 4.6)*
* Компонент должен определять необходимую сложность последующих заданий по результатам предыдущих попыток. *(ФТ 5.1)*
* Компонент должен рассчитывать начисляемые очки опыта и определять изменение магического ранга при достижении установленного порога. *(ФТ 6.2, 6.3)*

### 4.10. Взаимодействие с данными (Django ORM)
Django ORM обеспечивает чтение и запись структурированных данных посредством моделей Django.
* Компонент должен обеспечивать создание и получение записей учетных записей пользователей. *(ФТ 1.1, 1.2)*
* Компонент должен обеспечивать получение математических тем и связанных с ними теоретических материалов. *(ФТ 2.1, 2.3)*
* Компонент должен обеспечивать получение заданий, их форматов и эталонных ответов. *(ФТ 3.1, 3.4)*
* Компонент должен обеспечивать получение заранее подготовленных заданий для резервной выдачи. *(ФТ 3.7)*
* Компонент должен обеспечивать сохранение и выборку истории решений и данных об успеваемости. *(ФТ 4.1, 4.2, 4.3, 4.4)*
* Компонент должен обеспечивать чтение и обновление накопленного опыта, рангов и достижений обучающихся. *(ФТ 6.2, 6.3, 6.4)*

### 4.11. База данных (SQLite)
SQLite выступает основным хранилищем структурированных данных веб-приложения.
* В базе данных должны храниться учетные записи и сведения, необходимые для авторизации пользователей. *(ФТ 1.1, 1.2)*
* В базе данных должны храниться математические темы и соответствующие теоретические материалы. *(ФТ 2.1, 2.3)*
* В базе данных должны храниться заранее подготовленные задания, их форматы и эталонные ответы, необходимые в том числе при недоступности GigaChat. *(ФТ 3.1, 3.4, 3.7)*
* В базе данных должны храниться попытки решения, результаты проверки и сведения, необходимые для формирования статистики. *(ФТ 4.1, 4.2, 4.3)*
* В базе данных должны храниться накопленный опыт, магические ранги и полученные достижения обучающихся. *(ФТ 6.2, 6.3, 6.4)*

### 4.12. Сервис интеграции с GigaChat API
Сервис интеграции — серверный компонент, взаимодействующий с внешним API GigaChat. Требования данного раздела относятся к нашему сервису интеграции, а не к внутреннему устройству стороннего API.
* Сервис должен формировать запрос на генерацию задания с учетом выбранной математической темы. *(ФТ 5.2)*
* Сервис должен передавать при генерации определенный системой уровень сложности задания. *(ФТ 5.1, 5.2)*
* Сервис должен отправлять запросы на генерацию математических заданий через GigaChat API. *(ФТ 5.2)*
* Сервис должен принимать и обрабатывать ответы, полученные от GigaChat API. *(ФТ 5.2)*
* Сервис должен проверять пригодность полученного задания для предусмотренных форматов тренажера. *(ФТ 3.1, 5.2)*
* Сервис должен передавать подготовленное задание приложению заданий и тестов. *(ФТ 5.2)*
* При недоступности GigaChat API сервис должен инициировать выдачу заранее подготовленного задания из базы данных. *(ФТ 3.7)*

## 5. Критерии аттестации системы

### 5.1. Аттестация системы
Проверки выполняются в виде сквозных демонстрационных сценариев (плана демонстрации) в веб-браузерах на компьютере, планшете или смартфоне при наличии подключения к серверу. Используются тестовые учётные записи. Каждый критерий содержит комплексное действие, объединяющее несколько смежных шагов пользователя, и ожидаемый наблюдаемый результат, закрывающий группу функциональных требований (ФТ).

1. **Управление учетной записью и личным кабинетом (АТ 1)**
   * **Действие:** Пользователь вводит корректные данные на странице регистрации, создает учетную запись, сразу выполняет авторизацию в системе и переходит в личный кабинет.
   * **Результат:** Учётная запись успешно создана в базе данных, создана активная сессия входа, а в личном кабинете отображаются основные результаты обучения и начальные показатели.
   * **ФТ:** `1.1`, `1.2`, `1.3`

2. **Изучение теоретических материалов и выбор тем (АТ 2)**
   * **Действие:** Обучающийся открывает дашборд, просматривает список математических тем за 5 класс, выбирает конкретную тему и переходит к просмотру теоретических материалов.
   * **Результат:** Система корректно отображает структурированный список тем, загружает выбранный раздел и выводит соответствующие правила, формулы и примеры.
   * **ФТ:** `2.1`, `2.2`, `2.3`

3. **Тренажер заданий, проверка ответов и обратная связь (АТ 3)**
   * **Действие:** Обучающийся выбирает задание из темы, знакомится с его условием, вводит ответ в соответствующее поле ввода и отправляет его на автоматическую проверку с запросом разбора.
   * **Результат:** Система принимает решение, сопоставляет его с эталоном, выводит статус проверки (верно/неверно) и предоставляет текстовое объяснение правильного решения.
   * **ФТ:** `3.1`, `3.2`, `3.3`, `3.4`, `3.5`, `3.6`

4. **Сохранение результатов, статистика и анализ слабых мест (АТ 4)**
   * **Действие:** Обучающийся завершает серию заданий с допущением ошибок, после чего открывает общий раздел статистики, детализирует прогресс по отдельной теме и просматривает сформированные системой слабые места.
   * **Результат:** История попыток сохранена, показатели успеваемости пересчитаны, общий и детальный прогресс визуализированы, а проблемные темы выделены для повторной проработки.
   * **ФТ:** `4.1`, `4.2`, `4.3`, `4.4`, `4.5`, `4.6`

5. **Интеллектуальная генерация (GigaChat) и отказоустойчивость (АТ 5)**
   * **Действие:** Система в штатном режиме задействует ИИ-модуль GigaChat для динамической генерации задания и адаптации сложности на основе истории ученика; затем моделируется сбой внешнего API.
   * **Результат:** В штатном режиме ученик получает уникальную задачу от GigaChat; при разрыве соединения с API система мгновенно переключается на резервный источник и выдает подготовленное задание из локальной базы данных.
   * **ФТ:** `3.7`, `5.1`, `5.2`

6. **Игровой режим «Испытание», ранги и достижения (АТ 6)**
   * **Действие:** Обучающийся запускает игровой режим «Испытание», успешно проходит серию заданий, повторно закрепляет материал по старой теме, получает очки опыта, повышает магический ранг и проверяет профиль.
   * **Результат:** Игровой режим функционирует корректно, опыт начисляется, при достижении порога меняется магический ранг, а в профиле отображаются актуальные достижения.
   * **ФТ:** `2.4`, `6.1`, `6.2`, `6.3`, `6.4`
